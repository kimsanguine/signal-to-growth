## 왜 이 문장 순서인가

기존 README 상단(1~15행)은 제품 정의를 먼저 말하고 "왜 만들었나"로
넘어갑니다. 독자가 던지는 질문은 "이게 무엇인가"보다
"성장 프롬프트는 이미 많은데 이건 뭐가 다른가"에 가깝습니다.
그래서 A안은 **차별점 부정문("~가 아닙니다")을 두 번째 줄에 두고**, 그 뒤에
검증 가능한 근거 세 개를 붙입니다. 기존 README도 41행에서 같은 부정문을
쓰지만 화면 한 장 아래에 있습니다.

## 한계 문장 (본문에 유지할 것)

카피의 마지막 단락은 잘라내지 말고 유지하기를 권합니다.
이 제품의 판매 논리 자체가 "검증되지 않은 것을 검증된 것처럼 쓰지 않는다"인데,
상단 카피에서 한계를 지우면 제품 주장과 문서가 서로를 반박합니다.
[CLM-20260804-004] [CLM-20260804-005]

추가로, cross-runtime 문구는 각주가 필요합니다. 두 manifest가 같은 소스를
가리키는 것은 관찰된 사실이지만 [CLM-20260804-002], append-only 강제는 현재
Claude Code 훅으로만 구현돼 있습니다 [CLM-20260804-007].
문구 초안은 `readme-claim-corrections.md`에 있습니다.
