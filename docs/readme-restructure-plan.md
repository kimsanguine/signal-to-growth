# README 재배치 계획

이 문서는 **계획서**다. 아직 `README.md` 본문에 적용되지 않았다.
적용은 다른 도메인 worktree가 머지된 뒤 한 번에 수행한다
(그 전에 재배치하면 머지 충돌이 README 전체에 걸린다).

## 문제

현재 `README.md`는 약 590줄이고 순서가 이렇다.

```text
왜 만들었나 → 핵심 원칙 → 11개 스킬 → 설치 → 5분 로컬 체험 → CLI(약 200줄)
→ 실제 사용 예 → 안전과 승인 경계 → Artifact contract → 저장소 구조
→ 개발과 검증 → 경쟁 제품과 다른 점 → 프로젝트 상태 → 기여 → 출처 → License
```

처음 온 사람이 "일단 한 번 돌려보기"에 도달하려면 철학 2개 섹션과
스킬 표를 지나 약 145줄을 읽어야 한다. 그 뒤에는 Kakao 배포 절차 같은
운영자용 문서가 약 200줄 이어져서, 학습자가 실제 사용 예에 닿기 전에 끊긴다.

독자는 최소 세 종류인데 순서가 그중 하나(평가자)에게만 맞춰져 있다.

| 독자 | 원하는 것 | 현재 도달 거리 |
|---|---|---|
| 수강생 | 지금 당장 한 번 돌려보기 | 약 145줄 |
| 평가자 | 이게 뭐고 왜 다른가 | 즉시 (현재 최적) |
| 운영자 | Kakao·Supabase 배포 절차 | 약 283줄 |

## 재배치 원칙

1. **행동을 먼저, 설명을 나중에.** 첫 화면에서 실행 가능한 것 하나를 준다.
2. **철학은 유지하되 뒤로.** 삭제하지 않는다 — 이 저장소의 차별점이므로
   위치만 옮긴다.
3. **운영자용 절차는 별도 문서로 분리.** README에는 링크만 남긴다.

## 목표 순서

```text
1. 한 줄 정의 + 배지                     (유지)
2. 5분 로컬 체험                          ← 상단으로 이동
3. 수강생 권장 경로: Python 없이 preview  ← 상단으로 이동
   + six-part preview 목록 (이미 반영됨)
   + 학습자 시작 안내 링크
4. 11개 스킬 표                           (유지, 위치만 조정)
5. 실제 사용 예                            ← 앞으로 이동
6. 왜 만들었나 / 핵심 원칙                 ← 뒤로 이동
7. 안전과 승인 경계
8. Artifact contract
9. CLI 레퍼런스                            ← 뒤로 이동, 일부 분리 검토
10. 저장소 구조 / 개발과 검증
11. 경쟁 제품과 다른 점 / 프로젝트 상태
12. 기여 / 출처 / License
```
